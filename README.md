# Telegram UserBot

Многофункциональный юзербот на Telethon с RP-командами, загрузкой медиа (YouTube / Instagram / TikTok) и стелс-функциями.

## Запуск

```bash
pip install -r requirements.txt
python main.py
```

### Переменные окружения

| Переменная | Описание |
|-----------|----------|
| `API_ID` | API ID из my.telegram.org (обязательно) |
| `API_HASH` | API Hash оттуда же (обязательно) |
| `OWNER_ID` | Telegram ID владельца (обязательно) |
| `STRING_SESSION` | Строка сессии Telethon (опционально) |
| `PORT` | Порт Flask-статуса (по умолч. 8080) |
| `MEDIA_DIR` | Директория для скачанных файлов (по умолч. ./media) |
| `BOT_LANG` | Язык ответов: `ru` (по умолч.) \| `en` |
| `MAX_FILE_SIZE_MB` | Лимит отправляемого файла, МБ (по умолч. 4096) |

### Онлайн-следка (ONWATCH)
| Команда | Описание |
|---------|----------|
| `!onwatch [-m] @user\|ID <текст>` | Отправить текст, как только цель окажется в сети (`-m` — markdown) |
| `!onwatchlist` | Список активных треков (с текущим статусом) |
| `!unonwatch @user\|ID` | Снять отслеживание |
| `!onwatchstatus @user\|ID` | Снимок трека: статус, сессия, кулдаун, счётчик отправок |
| `!onwatchlog @user\|ID [7d]` | История сессий цели: когда заходил, сколько был, каким каналом поймано |

Каналы детекции (максимальная точность): событие `UpdateUserStatus` (мгновенно), адресный опрос статуса с адаптивным интервалом (база 5–35 с, после реконнекта — внеплановый батч `get_users`), typing-апдейты, входящие сообщения и галочки. Плюс бесплатные «боковые» сигналы активности: смена имени/username, новая сторис, реакция на ваше сообщение, входящий звонок (самый сильный — человек был в сети секунду назад) и правка своего сообщения в ЛС. Всё, кроме смены профиля, учитывается только в ЛС с вами.

Источники в истории (`!onwatchlog`, колонка `source`): `status` (реальный вход по
статусу), `flicker` (пропущенная сессия по `was_online`), `poll`/`update` (поллер и
событие, с суффиксами `-recently`/`-flicker`), `typing`, `message`, `read`,
`update-profile`, `update-story`, `update-reaction`, `update-call`, `update-edit`.
Отдельно, только строкой истории без уведомления: `reaction-group` (реакция в общем
чате) и `story-channel` (сторис канала, где цель — автор). При добавлении нового
канала источник нужно внести в `_ACTIVITY_LOG_SOURCES`, иначе он не попадёт в историю.

Тон уведомления во внешний бот различается по каналу: 📞 звонок, 📸 сторис,
📝 профиль, ✏️ правка, 💬 typing, 👍 реакция, 👁 прочитано; обычный вход и
flicker — нейтральное «появился в сети». Каждая пара «эмодзи + подпись»
уникальна (закреплено тестом).

Одно уведомление на непрерывную сессию: кулдаун 120 с страхует от дребезга статуса, а флаг сессии (`last_activity`, таймаут 15 минут тишины) не даёт повторять отправку, пока человек продолжает переписываться. История сессий хранится 90 дней и чистится периодической задачей поллера.

Мгновенность: `UpdateUserStatus` обрабатывается сразу. `connection_watcher`
опрашивает `client.is_connected()` раз в 2 с и после реконнекта запрашивает
внеплановый батч-опрос, не дожидаясь шага поллера. Это скорость реакции на уже
зафиксированный разрыв, а не скорость его обнаружения: мёртвый link Telethon
замечает по своим внутренним таймаутам, поэтому фактическая задержка =
внутренний таймаут клиента + до 2 с. `catch_up` у клиента намеренно выключен:
накопленные за оффлайн апдейты пришли бы с опозданием и переписали бы статус
задним числом, а пропущенную сессию караул определяет по `was_online` (flicker)
с реальным временем выхода.

Эксплуатация: сторож соединения не умирает от ошибок (лог и повтор через 5 с),
флаппинг связи дебаунсится (не чаще одного батч-опроса за 20 с), неудачный
прогрев повторяется с паузой 15 с, после трёх неудач — откат на поштучный
опрос, и через 5 минут батч пробуется снова: деградация временная. Сброс
расписания помечается поколением — если реконнект случился во время прогрева,
устаревшие сроки не записываются, и цикл начинается заново.

Что покрыто только живой сессией (юнит-тесты сюда не достают):
- разрыв и восстановление реального MTProto-link, включая внутренние таймауты Telethon;
- фактическая доставка сервером `UpdateReadHistoryOutbox` (галочки в ЛС);
- реальные значения `was_online` у целей с видимым last-seen (flicker-окно на настоящих данных).

Остальное — статус-апдейты, typing, in-ЛС сообщения, галочки, flicker и
сессионная модель — проверяется wire-тестами: объекты сериализуются и
разбираются обратно через `BinaryReader`/`from_reader`, а события собираются
штатными builders Telethon (`UserUpdate.build`, `MessageRead.build`).

Ограничение слоя Telethon 1.44: `UpdateUserPhoto` (смена аватара) и `UpdateStoryViews` (кто посмотрел вашу сторис) в этой версии не доставляются отдельными апдейтами — каналы появятся вместе с библиотекой.

Пропущенные сессии (flicker по `was_online`) требуют Telethon ≥ 1.37.

### RP-команды

Работают **только в личных сообщениях**. Для отправки RP-действия:

- **Любой пользователь** в ЛС — пишет команду, бот отвечает
- **Owner/Sudo** — реплай на чьё-то сообщение с командой (RP от имени бота к этому человеку)

Более 90 RP-действий. Список: `!rphelp`

## Зависимости

- `telethon` — работа с Telegram API
- `yt-dlp` — загрузка YouTube / TikTok / Instagram (видео, аудио, карточки)
- `curl_cffi` — обязателен для TikTok/Instagram (имперсонация браузера в yt-dlp)
- `requests` / `aiohttp` — HTTP-запросы
- `flask` — веб-статус

## Структура

```
├── main.py          # Bootstrap: Flask /stats, стартовые задачи, загрузка плагинов
├── plugins/         # Команды, сгруппированные по доменам (14 модулей)
│   ├── system.py    #   статус, пинг, sudo, рестарт…
│   ├── stealth.py   #   ghost/cover/silent/shadow…
│   ├── media.py     #   !dl / !audio / !playlist / !ytupdate…
│   ├── watch.py     #   !onwatch + поллер статусов
│   └── …            #   profile, games, toolbox, messages, datanote, afk,
│                    #   chatinfo, security, rp, menu
├── helpers.py       # Общие функции (сущности, FloodWait, карточка статуса)
├── core.py          # Состояние бота, owner_filter, respond, кулдауны
├── config.py        # Конфигурация и константы
├── help_data.py     # Справка и меню с кнопками
├── downloaders.py   # Загрузчики YouTube / Instagram / TikTok (прогресс, очередь)
├── notifier.py      # Внешний уведомляющий бот
├── rp_commands.py   # RP-команды (словари)
├── storage.py       # Хранилище (SQLite)
├── tests/           # Юнит-тесты: python -m unittest discover -s tests -v
├── requirements.txt # Зависимости
├── build.sh         # Скрипт сборки для хостинга
└── media/           # Папка загрузок
```
